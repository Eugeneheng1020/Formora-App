# 写实施计划

方案说的是「做成什么样」，计划说的是「按什么顺序做，做到哪一步算完」。多步任务
没有计划，用户就只能盯着你一直在说话，不知道还剩多少。

## 什么时候用

- 一件事要三步以上才能做完
- 用户说了「先规划再做」或用了 `/plan`
- 你要动的东西跨了多个文件、多个岗位

## 怎么做

### 1. 先把步骤列出来，再动手

用 `plan` 工具的 `init` 把步骤写进去。每一步要满足：

- **一步只做一件事**，做完能单独验证
- **步骤名说的是结果，不是动作**：写「购物车页面能显示优惠券」，不是「改代码」
- **写清楚要动哪些文件**：会新建或修改哪几个，用户一眼看得出这一步的范围
- 三到八步之间。多于八步说明这件事该先拆，少于三步说明不需要计划

### 2. 边做边报

开始一步用 `start`，做完用 `done`，做不了了用 `drop` 并说明原因，中途发现漏了用
`append` 补。**每一步做完就更新**，不要攒到最后一次性打勾——计划的价值在过程中，
不在结束后。

### 3. 每步都留下可验证的东西

一步做完，说清楚三件事：改了哪些文件、怎么验证它真的成了、下一步是什么。
文件用 `write` / `edit` 落盘，路径写进回复里。

### 4. 遇到拿不准的，停下来问

计划执行中发现方案有洞——比如两种做法差别很大、或者用户没说过的取舍——用 `ask`
把选择摆出来，不要替用户选了闷头做下去。

## 三条纪律

- **不写空话步骤。** 「处理边界情况」「补充测试」「优化一下」不是步骤；写清处理哪几种
  情况、测什么、改成什么样。
- **改了计划要说。** 加步骤、删步骤都要让用户看见，`plan` 工具会把完整进度回显。
- **最后一步永远是验证**，不是「完成」。
