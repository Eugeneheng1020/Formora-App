# 接 MCP 服务

MCP 是一套让 App 连上外部服务并拿到它工具的协议。接进来之后，那个服务的工具会
直接出现在 Agent 的工具列表里。

## 什么时候用

- 用户说「能不能连上 Linear / GitHub / Notion / 我们内部的某个服务」
- 用户想让 Agent 直接读写某个外部系统，而不是自己复制粘贴

## 三步

### 1. 先看目录里有没有

`mcp_catalog` 列出内置推荐目录。目录里的条目端点都是核实过的，一步就能加。
把匹配的那条报给用户，说清楚它能干什么、要怎么鉴权（浏览器登录还是填令牌）。

### 2. 添加

`mcp_add` 传服务的名字、传输方式和端点。

- 目录里的：照抄目录给的值
- 用户自己的服务：问清楚**端点 URL** 和**鉴权方式**再加，不要猜
- 用户手里有一段 JSON 配置（Claude Desktop / Cursor 那种）：直接读那段配置里的
  `command` / `args` / `url`，不要让用户手打

**stdio 类型的服务只有官网版支持**，而且要机器上真装了 node 或 python。
如果用户装的是 App Store 版，直接说清楚这条服务接不了，别让用户白试。

### 3. 测试连接

`mcp_test` 跑一次真实握手。这一步不能省——加进去不等于连得上。

- 连上了：把它暴露的工具列出来给用户看
- 401：需要登录，告诉用户去「设置 → MCP」那一行点浏览器登录
- 连不上：把错误原样报出来，不要翻译成「可能是网络问题」

## 接完之后

告诉用户：**去「Agent → 那个 Agent → MCP」把这个服务打开**，并选「全部工具」或
指定几个。装在全局，开关在每个 Agent 自己身上。

## 三条纪律

- **端点和鉴权方式不要猜。** 猜错的结果是一个连不上的条目留在列表里。
- **测试连接必须做**，把真实结果报出来。
- **写一个新的 MCP 服务器不在这个技能里。** 那要在机器上装 node/python 并起一个
  进程，Formora 的沙盒跑不动；用户真要写，请用户在终端里写，写完再用这个技能接进来。
