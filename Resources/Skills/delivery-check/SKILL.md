# 交付自检

「我做完了」和「我验过了」之间隔着一整类事故。这个技能是在交付前把这段距离走完。

## 什么时候用

- 你准备说「完成了 / 好了 / 改好了 / 通过了」
- 用户用了 `/review`
- 一轮多步任务的最后一步

## 怎么做

### 1. 先回到用户最初那句话

把用户一开始要的东西重读一遍（往上翻，或 `read` 那份需求文档）。**逐条对**，
不是凭印象对。用户要了三件事，你做了两件，现在就是说出来的时候。

### 2. 按类型验

| 交付物 | 怎么验 |
|---|---|
| 写进项目的文件 | `read` 把它读回来，确认内容真的在里面、格式没坏 |
| 改动的代码 | `bash` 跑构建 / 跑测试，把真实输出贴出来 |
| 一份文档 | 逐条核对验收标准，哪些满足了、哪些没有 |
| 一个结论 | 说出它是从哪几条证据推出来的 |
| 另一个 Agent 或子任务交回的结果 | 自己打开文件、跑一遍，不要只转述它说的「做完了」 |

**验证必须是这一轮刚跑出来的输出。** 之前跑过的不算——改过之后要重跑；没有输出的
验证等于没验。

### 3. 三件事写在结尾

1. **做了什么**：文件路径、改了哪几处
2. **怎么验的**：命令和它的真实输出（不是你以为的输出）
3. **没做的 / 没验的**：明确列出来，说明为什么

### 4. 不确定就承认

跑不了测试（没有测试、环境不具备），就写「没有跑测试，因为 X」。
**不要用「应该没问题」「理论上可以」收尾**——那是把风险留给用户，而用户还不知道。
话里冒出「应该」「大概」「看起来」，就说明还没验。

## 三条纪律

- **先验证，后声明。** 顺序反了，声明就是猜测。
- **失败要原样报告。** 测试红了就说红了，贴输出，不要挑一句好听的说。
- **部分完成也是一种完成**，但必须说清楚部分在哪。
